# Phase 9.2 Plan 07 : installateur à deux clés et documentation du chemin local Summary

L'étape `utilisateur` de l'installateur autorise la clé du Mac à côté de celle de GitHub (deux lignes `restrict,command=` au plus, sans doublon). Le RUNBOOK, l'ADR-063 et le README documentent `ci:local` et `deploy:local` tels que le code les implémente. Le tout est épinglé par des tests.

## Ce qui a été fait

- **Tâche 1** (c9bc528 rouge, 109da0d vert) : `--cle-publique` accepte une ou deux lignes `ssh-ed25519` distinctes, écrites dans l'ordre du fichier et comparées par `cmp`. Le script refuse (code 4) une troisième ligne (« --cle-publique : deux lignes au plus (clé de GitHub et clé du Mac) »), une « clé en double », une ligne vide, un fichier vide ou un autre type de clé. `cles_autorisees_conformes` exige une ou deux lignes, le préfixe exact sur chacune et aucun doublon. En-tête et usage sont à jour. Avec une seule clé, rien ne change. `/bin/bash -n` passe (bash 3.2).
- **Tâche 2** (99f3093) :
  - Section du RUNBOOK avec 13 sous-sections : Pourquoi, Prérequis, Fichier local, Créer la clé, Autoriser la clé, ci:local, deploy:local, état, retour, gel, pannes, journal, coexistence avec GitHub et règle pour les agents.
  - Une ligne de renvoi en tête de « Déploiement » et de « Retour arrière ».
  - ADR-063 et README.
  - Nouveau describe dans `tests/repo/docs.test.ts` (9 cas).

## Constats du code par rapport aux plans (pour le plan 08)

1. **`--dry-run` exige le fichier local complet** : `deploiement.env` lisible en 0600, clé du Mac et `.pub` présents, `known_hosts-deploy` non vide. Il prend aussi le verrou. La répétition à blanc de l'orchestrateur (D-13) ne peut donc venir qu'après la création de la clé par Erwan et l'écriture de `deploiement.env`.
2. `--dry-run` lance `ci:local` complet (long) si aucun reçu vert n'existe. Il fait aussi un vrai `npm ci` (réseau vers le registre npm) dans le worktree.
3. `deploy:local` n'a pas d'option `--aide` : une option inconnue affiche l'usage (code 2). `ci:local -- --aide` existe.
4. `retour` rend les codes 0 à 3 (pas 4 ni 5). `etat` rend 0, 1, 2, 3 ou le code du serveur ou de ssh. Un verrou tenu rend le code 2.
5. `--urgence` sur un déploiement passe aussi outre « rien à déployer ».
6. Sans `RTP_RSYNC`, le défaut est `rsync`, cherché dans le `PATH`.

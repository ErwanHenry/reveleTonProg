**Confirmation mechanism (orchestrator decision « bloquant 1 », said honestly):**
- `confirmerSurTerminal(phrase)`: opens `/dev/tty` with `fs.openSync('/dev/tty', 'r+')` (failure: Sortie code 3 « aucun terminal : la confirmation doit être tapée par Erwan »), writes « Pour confirmer, tapez exactement : <phrase> », reads bytes with `fs.readSync` until a newline, closes; `verifierPhrase(saisie, phrase)` compares after removing the trailing newline only (no trim, no case folding); mismatch: Sortie code 3 « confirmation refusée : rien n'a été envoyé ».
- `type Confirmateur = (phrase: string) => Promise<void>`. `executerRetour` (and plan 06's `executerDeploiement`) take `ctx.confirmer` as a required parameter, without default. Tests pass a fake confirmer. `scripts/deploy-local.ts` always passes `confirmerSurTerminal`; its exported `Dependances` has no terminal, line reader or confirmer field (plan 04 contract). The stdin check `process.stdin.isTTY !== true` (non injectable, read in the CLI) gives exit 3 first, before lock, config, build or server, unless `--dry-run`.
- Header comment and ADR-063 (plan 07) say it plainly: any code running as Erwan could import the library and pass its own confirmer, or wrap the CLI in a pseudo-terminal; the typed phrase guards against mistakes, not against an attacker; the real barrier is the key passphrase (plan 03), which only Erwan types.
- `phraseAttendue(action, cible, sha | null)`: sha7; null gives `precedente`; production inserts `en production`.
- `lignesEcran(infos)`: pure; target in capitals for production, commit and subject, online version, receipt date, files changed, fingerprint, rsync variant, freeze decision; absent fields not printed; no host, user or URL field exists.

**Journal and lock:** `EntreeJournal = { date; action: 'deployer' | 'retour' | 'retour-auto'; cible; commit: string | null; precedent: string | null; resultat: 'succes' | 'echec' | 'refus' | 'retour-auto' | 'sans-retour'; urgence: boolean; justification?: string; message?: string }` (message passed through `masquer`, 300 characters max). `ajouterJournal(home, entree, cfg)` validates every field, refuses unknown keys, dir 0700, file 0600, one line; a write failure is a warning only. `prendreVerrouDeploiement(home)` = `prendreVerrou` of plan 01 on `~/.cache/rtp/deploiement/.verrou` (comment: WR-02 equivalent; the server flock still serializes with GitHub).

**`executerRetour({ version, urgence, justification, dryRun }, ctx)`** order: lock; lireConfig; resoudreExecutables; decisionGel (refused or urgence without valid justification: exit 1); version '' or 40 hex (else exit 2); `--dry-run`: print what would be done (target, version or « précédente », freeze decision) and « répétition à blanc : aucun contact avec le serveur », exit 0, no agent; else ouvrirAgent (passphrase), etat (courant before), screen, `ctx.confirmer(phrase)`, decisionGel again with a fresh `maintenant()` (CR-02), verb `retour <cible> [<version>]`, etat (courant non null and equal to version when given), versionServie if cfg.url (commit = courant; URL empty: « vérification HTTPS sautée : RTP_URL vide » in plain words), journal, finally agent closed and lock released. Exit codes: 0, 1 guard or check failed, 2 usage or config, 3 not a terminal, confirmation refused, or key without passphrase. Print UTC start and end like rollback.yml.

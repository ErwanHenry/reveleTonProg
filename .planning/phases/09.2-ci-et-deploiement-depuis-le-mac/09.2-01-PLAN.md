**Design (Claude's discretion, D-01 to D-03):**
- Steps run in the main working tree, in this order: verifier steps, then secrets, then e2e (the longest last). `npm ci` is replaced by `npm ls --all` (research §1: rebuilding `node_modules` of Erwan's tree at each check on a loaded machine is not wanted; the deployment build does a real `npm ci --ignore-scripts`, plan 02). Playwright install is `npx playwright install chromium` (no apt on macOS).
- ids.lock base: `git fetch --quiet --no-tags origin main` first (failure: warning, existing `origin/main` kept), then base = `git merge-base HEAD origin/main`; if the base equals HEAD (commit already pushed), base = `HEAD^1`; same fail-closed cases as ci.yml (base commit missing: step fails; `ids.lock` absent from base: step ok with the message « ids.lock n'existe pas dans le commit de base »). The base is written in the receipt.
- Receipt `~/.cache/rtp/ci/<sha>.json`, `version: 1`. Written only if the tree was clean (`git status --porcelain --untracked-files=all` empty) at the start and at the end and HEAD did not move; otherwise the run says why no receipt is written. A partial run writes a receipt with `partiel: true` (never valid).
- Exit codes: 0 every executed step ok (secrets « non exécutée » included, with the sentence « recherche de secrets non exécutée : ce reçu ne permet pas de déployer ») ; 1 a step failed (the run goes on to the end so the receipt lists every result) ; 2 usage, Node other than 24, not a git repository, lock held.
- Lock: directory `~/.cache/rtp/ci/.verrou` created by `mkdirSync` (atomic), file `pid` inside; held by a live pid (`process.kill(pid, 0)`): exit 2; dead pid: taken over with a warning. Released in `finally` and on SIGINT/SIGTERM.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mac user session -> receipt file | any process of Erwan's session can write `~/.cache/rtp/ci/` |
| ci:local -> npm dependency code | npm test, builds and e2e run dependency code in the main tree (no key is involved at this stage) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09.2-01 | Spoofing | receipt `~/.cache/rtp/ci/<sha>.json` | accept | A receipt only proves a check ran; it authorizes nothing. Plan 06 shows its date on the confirmation screen; the barrier stays the typed confirmation and the key passphrase (research §4.5) |
| T-09.2-02 | Tampering | receipt for a modified tree | mitigate | Written only if `git status --porcelain --untracked-files=all` is empty at start and end and HEAD unchanged; partial runs are `partiel: true`; tested |
| T-09.2-03 | Information disclosure | child process environment | mitigate | `envDeBase` whitelist: no SSH_AUTH_SOCK, token or RTP_ variable reaches npm code; tested with a child printing its env |
| T-09.2-04 | Repudiation | silent skip of the secrets scan | mitigate | « non exécutée » in plain words, `secrets: 'non_executee'` in the receipt, refused by `recuValidePourDeploiement`; tested |
| T-09.2-05 | Tampering | drift between local and GitHub checks | mitigate | parity test on step names, order, run strings and RTP_ env, with mutation cases |
| T-09.2-06 | Denial of service | two concurrent runs building in the same folder | mitigate | `mkdir` lock with pid, stale lock takeover; tested |
</threat_model>

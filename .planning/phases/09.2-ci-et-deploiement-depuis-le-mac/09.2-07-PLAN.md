**Design:**
- Installer (bash 3.2 on the Mac, bash 5 on the server): up to two non-blank lines from `--cle-publique`, each matching `RE_CLE`, keys (second field) distinct; more: exit 4 « --cle-publique : deux lignes au plus (clé de GitHub et clé du Mac) ». Expected content: one `"$PREFIXE_CLE $cle"` line per key, input order, compared with `cmp`. `cles_autorisees_conformes`: one or two lines, exact prefix, valid key, no duplicate. Header and usage say « une ou deux lignes ». One-key behaviour unchanged; only the « une seule ligne attendue » case is updated.
- RUNBOOK `## CI et déploiement depuis le Mac`, before `## Incidents fréquents`, French, no em or en dash, no host, user, address or URL value: placeholders `<hôte>`, `<utilisateur>`. Subsections:
  - Pourquoi: fact of 2026-11-18 (public repository, free GitHub minutes, Erwan's informed choice).
  - Prérequis: Node 24 (fnm), `brew install gitleaks`, `brew install rsync` (rsync 3 required: openrsync is refused for a send), `sandbox-exec`, jq.
  - Fichier local `deploiement.env`: keys table (from `CLES_CONFIG`), mode 0600.
  - Créer la clé du Mac (Erwan, dans son terminal, jamais un agent): `umask 077 && ssh-keygen -t ed25519 -C rtp-deploy-mac -f ~/.config/rtp/rtp-deploy-mac` with a passphrase kept in Vaultwarden; the main session only reads `rtp-deploy-mac.pub`; a key without passphrase is refused by every subcommand that contacts the server.
  - Autoriser la clé sur le serveur: two-line public file, installer step `utilisateur` after Erwan's agreement, `--verifier`, way back (reapply with GitHub's key alone).
  - Contrôler: `npm run ci:local`, receipt path, gitleaks « non exécutée ».
  - Déployer: screen, phrases, `--dry-run` (never contacts the server: guards, receipt, sealed build only), `--forcer`, exit codes 0 to 5; the phrase is read on the terminal.
  - Lire l'état: `npm run deploy:local -- etat` (passphrase required).
  - Retour arrière: `npm run deploy:local -- retour [<sha>]`.
  - Gel et retrait d'urgence: `--urgence --justification`.
  - Pannes: openrsync refused (`brew install rsync`, `RTP_RSYNC`), gitleaks absent, key without passphrase, lock held, fetch impossible, intégrité locale modifiée, exit 4 and 5, sandbox-exec missing, sandbox tests left to the main session.
  - Journal: `~/.local/state/rtp/deploiements.jsonl`, masked identifiers.
  - Coexistence avec GitHub: workflows untouched, D-11 pending, server lock, reject unwanted GitHub waiting runs.
  - Règle pour les agents: only `--dry-run`, which never contacts the server; never `script`, `expect` or any pseudo-terminal around deploy:local; the first real `etat` and every real deployment are Erwan's.
  One line at the top of « Déploiement » and « Retour arrière » points to the new section.
- ADR-063 after ADR-062 (Contexte / Décision / Conséquence): Erwan's choice; two commands and the receipt; guards equal to the deploy job; build sandbox (write deny, secret read deny, snapshot) and its same-user limit; dedicated key with passphrase created by Erwan, forced command, two-key installer; « La barrière réelle est la phrase de passe de la clé, que seul Erwan tape. La phrase de confirmation tapée protège contre l'erreur, pas contre un attaquant : tout code lancé sous l'utilisateur d'Erwan peut appeler la bibliothèque ou simuler un terminal. »; rsync 3 required; dry run without server contact; GitHub workflows unchanged (D-11).
- README: under « Lancer en local » a paragraph with both commands pointing to the RUNBOOK; under « Où sont les secrets » `~/.config/rtp/deploiement.env` and the passphrase-protected Mac key.

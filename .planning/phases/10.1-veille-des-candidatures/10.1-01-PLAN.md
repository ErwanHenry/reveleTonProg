# Plan 10.1-01 : motif à décider et classement de la veille

## Objectif

Corriger le constat F-03 (désistement sans motif décidé qui arrête la répétition à blanc) et produire, à partir des données que l'import calcule déjà, le classement « sorties, entrées, retours, à décider » de la demande d'Erwan.

## Tâches

1. **Cas rouges** (`tests/import/import-cli.test.ts`, `tests/veille/classer.test.ts`) : racine temporaire fictive, une personne `declare` dont la ligne amont passe à `renonce` sans motif dans la table ; `--dry-run` texte, markdown, json ; import réel refusé ; classement de cas fictifs (sortie avec ralliement déjà décidé, sortie sans motif, entrée d'une personne connue, entrée à décider, retour, changement pressenti vers declare, dérive seule qui ne compte pas).
2. **CLI** : dans la boucle de `scripts/import-datagouv.ts`, détecter avant `mapRow` une ligne `renonce` dont la correspondance n'a pas de motif ; en répétition, la mettre de côté (`motifsADecider`) ; en import réel, refuser avec le message prescrit. Ajouter `json` aux valeurs de `--format` (stdout : un seul objet JSON ; tout le reste sur stderr). Le texte et le markdown gagnent une ligne « motif à décider » ; le module `rapport-import.ts` n'est pas modifié (la ligne est ajoutée par la CLI sous la section « Nouveaux à décider » par un champ facultatif si nécessaire, sinon dans une section ajoutée en fin de rapport avant la phrase finale).
3. **Module pur** `scripts/lib/veille/classer.ts` : importe `statutLePlusRecent`, `dansPerimetre` d'`equite.ts` (aucune copie) et les helpers d'échappement exportés de `rapport-import.ts` (exporter `enCode`/`propre` si besoin, sans changer la sortie) ; produit le classement et `resumeVeilleMarkdown` (section « Veille : résumé » avec comptes et listes) et `detailsLocauxMarkdown` (texte amont non relu).
4. Vert, `npm test` ciblé, `npm run check`.

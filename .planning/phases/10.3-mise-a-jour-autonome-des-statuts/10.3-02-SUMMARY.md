# Phase 10.3 Plan 02: clé automatique restreinte côté serveur Summary

Commande forcée `--auto` (production seulement, quatre verbes, retour limité à la version précédente), installateur qui écrit la troisième ligne `authorized_keys` seulement sur un script à jour, faux serveur qui joue ce mode.

## Réalisé

- **Tâche 1** (`5771af4`) : `AUTO` posé par le seul argument `--auto` ; tout autre argument refusé (64) avant la lecture de SSH_ORIGINAL_COMMAND. Production seulement pour envoi, `activer`, `etat`, `retour`. `retour production <sha>` accepté seulement si le sha vaut PRECEDENT. Marqueur `# rtp-capacite: auto-v1` en ligne 2, champ `"auto":true|false` dans chaque ligne de journal.
- **Tâche 2** (commit installateur) : `--cle-publique-auto` (une ligne ed25519, doublon avec les clés manuelles refusé, code 4 ; sans `--cle-publique` code 2). L'écriture exige le marqueur dans `$SBIN/rtp-deploy-command` (code 4 en application, « a faire » en vérification). Conformité de `authorized_keys` : une à trois lignes, deux manuelles au plus, une automatique au plus. Réappliquer sans l'option retire la ligne (testé).
- **Tâche 3** (`43f02cd`) : `modeAuto` dans `creerFauxServeur` ; le faux ssh lance `bash SCRIPT --auto` et répond 255 sans `-o IdentityAgent=none` et `-i` lisible.

## Hypothèse A1 (man sshd)

Phrase lue dans `man sshd`, section AUTHORIZED_KEYS FILE FORMAT, option `command="command"` : « Specifies that the command is executed whenever this key is used for authentication. The command supplied by the user (if any) is ignored. » Le client ne fournit donc que SSH_ORIGINAL_COMMAND ; l'argument `--auto` écrit dans la ligne par root n'est pas modifiable par lui.

## Écarts

- **[Rule 1] Test existant adapté** : le test « consigne une ligne JSON » attendait l'objet exact sans `auto` ; il attend maintenant `auto: false` (conséquence voulue du nouveau champ).
- **[Rule 1] Messages de l'installateur** « une ou deux lignes restreintes » changés en « une à trois lignes restreintes » (prévu par le plan) ; les attentes de tests existantes mises à jour en conséquence.
- Le faux ssh vérifie `-o IdentityAgent=none` et `-i` lisible uniquement en modeAuto ; les autres modes sont inchangés (`-i` et `-o` sont toujours sautés).

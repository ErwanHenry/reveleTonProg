<objective>
Construire le relecteur automatique de D-03 : un agent `claude -p` sans outil, dont la sortie est un verdict contraint (`confirme | infirme | insuffisant`, une citation, une date), vérifié par du code, appelé deux fois (vérification puis contre-vérification adverse) ; et la récupération du texte des sources qu'il lit. Plus un lecteur strict commun de fichiers de configuration locale, réutilisé par le plan 10.3-05 pour le moyen de push.

Purpose: SC-1 exige des statuts et cases relus par agent d'IA ; SC-2 exige que tout doute bloque. La conception (agent sans outil, texte fourni par le code, citation retrouvée mot pour mot, deux agents) est le rempart contre l'injection de prompt venue du jeu public ou des pages.
Output: config-locale.ts, agent-claude.ts, sources-texte.ts, faux claude, tests.

Contraintes de session : aucun appel réel à `claude` ni au réseau dans les tests (faux claude, fetch injecté) ; aucune écriture dans ~/.config/rtp/ (HOME temporaire dans les tests) ; aucune dépendance npm.
Choix à confirmer par Erwan (question ouverte 5) : le code supporte les deux voies ; le jeton `claude setup-token` est la voie par défaut, choisie à l'installation.

  <action>
1. Write `src/lib/content-core/astro-loader.ts` from RESEARCH Pattern 4. It is an object loader with deliberately NO `schema` and no `parseData`, and imports `import type { Loader } from 'astro/loaders'`.
   - Roots: projectRoot = `fileURLToPath(config.root)`, contentRoot = `resolveContentRoot(projectRoot)`, schemasDir = `schemasDirOf(projectRoot)`.
   - Use a module-level memo keyed by a fingerprint: the sorted relative path + mtimeMs + size of every file under `<contentRoot>/src/content` and `<projectRoot>/schemas`. The 8 loaders then share ONE loadAll per sync. A `reported` flag makes the first loader log the diagnostics once (A5, verified by the parity test and skeleton.test case c).
   - On errors: call `logger.error(formatText(d))` for each diagnostic, first loader only. Then throw `content-core : <n> erreur(s) de contenu, build interrompu` when `watcher` is undefined (build). In dev, return and keep the previous data.
   - On success: `store.clear()`, then `store.set({ id, data, digest: generateDigest(data), filePath })` for each of this collection's entries, with filePath relative to projectRoot.
   - In dev, call `watcher.add(<contentRoot>/src/content)` and re-run on change/add/unlink under `/src/content/`.
2. Write `src/content.config.ts`. Import `defineCollection` from `astro:content` and the loader with a relative `.ts` import. Export `collections` as 8 explicit lines, `candidats: defineCollection({ loader: contentCoreLoader('candidats') })` and the same for themes, mesures, sources, couverture, glossaire, sondages, journal.
   - No `schema`, no Zod, no `reference()`, no `glob()`/`file()`. A second parser would reintroduce Date objects (anti-pattern).
3. Write the parity test. Run it and `fnm exec --using=24 npm run check` (0 errors). Commit as `feat(01-04): add Astro object loader on content-core`.

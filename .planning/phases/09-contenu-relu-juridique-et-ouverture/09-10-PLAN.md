**Content rule (CONTEXT constraints, D-04):** in `src/content/**` only the review tool writes, and only review fields (`statut_relecture`, `relecteur`, `date_relecture`, `verifie_le`, `verifie_par`). A wording, a quote, a date of a status, a state of a case is corrected by Erwan himself in the YAML, or by the orchestrator applying a diff that Erwan read and validated word for word in the conversation. No agent corrects a text on its own, proposes a « better » wording unasked, or marks anything `relu` on Erwan's behalf from the command line: the marks come from Erwan's clicks in the page or from commands he runs. Never edit `archives/**`.

**Workspace:** the review runs in its own git worktree and branch so that other plans can use the main working tree at the same time. Push at least once per review session (golden rule: nothing useful stays local more than 24 hours). Commits by the orchestrator carry the trailer `Co-Authored-By: <modèle qui fait le commit> <noreply@anthropic.com> (Claude Sonnet 5.5 ou Claude Opus 5.5 selon l'agent)`. Pushes to the branch run the CI checks but request no deploy; the merge into main touches the site and requests a deploy to `essai`.

**Scope (D-06):** santé only. Travail and Europe et monde are not reviewed. Only statuses whose code is in the equity perimeter are reviewed; the tool refuses the others.
